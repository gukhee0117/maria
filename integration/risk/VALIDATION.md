# 추가 통합 검증 결과와 남은 범위

기존 기능·DB 구조·계산식·API 경로·3거래일 만료 정책을 변경하지 않았다. 운영 DB·NCP·자동 동기화는 적용하지 않았고 Git 스테이징·커밋도 하지 않았다.

## 추가 실제 HTTP: 3개 통과

Python의 실제 create_app·GET /grades·Pydantic 직렬화·SQLite 게시/만료 코드를 Uvicorn으로 실행하고, MARIA의 실제 RestClient·DTO·저장 트랜잭션·이름 잠금·재시도·공통 조회를 연결했다. HTTP와 DB를 모의 응답으로 대체하지 않았다. 가격과 달력은 합성 데이터이며 KIS·운영 키는 사용하지 않았다.

1. **응답·멱등성·정정·부분 게시:** priceTo·최초 버전 1·KST 소수초가 있는 asOf의 순간 일치, 첫 저장, 동일 응답 중복 수신 시 행/시각 보존, Python 재계산 게시 버전 2 수신, 뒤늦게 두 번째 종목 게시 및 기존 종목 중복 처리를 확인했다.
2. **실제 503·재시도·EXPIRED 제외:** 테스트 Python SQLite를 잠시 분리해 실제 API 503을 발생시켰다. DB 사본은 보존되고 재시도 상태가 저장됐다. 3거래일까지 사용 가능하고 4거래일부터 MARIA가 차단했다. Python DB 복구 후 실제 GET /grades는 빈 배열을 반환했고 RETRY 성공 뒤에도 과거 등급은 되살아나지 않았다.
3. **전역 UTC와 세션 KST:** 테스트 DB 전역/세션이 UTC일 때 저장·사용은 의도대로 차단됐다. 테스트 전용 위험등급 DataSource의 세션만 KST로 설정하자 전역 UTC를 유지한 채 정상 저장·초 단위 DATETIME 재조회·동일 버전 중복 수신이 통과했다. 운영 연결 풀을 변경한 것은 아니다.

실행된 JUnit 보고서: PythonRiskHttpIntegrationTest 3 tests / 0 failures / 0 errors / 0 skipped. 종전 MARIA 전체 1,436개 통과 기록과 구분한다. 이번에는 추가 통합 테스트만 실행했고 기존 전체 테스트를 불필요하게 재실행하지 않았다.

## 전체 구조·합성 데이터 이관: 3개 통과

운영 DB 복사본은 제공받거나 조회하지 않았다. 대신 저장소의 이관 전 전체 DDL을 임시 컨테이너의 별도 스키마에 재현했다. 기존 51개 테이블이 있었고 승인된 동기화 상태 테이블 추가 후 52개가 됐다. 이는 테스트 결과이며 새로운 운영용 테이블 추가가 아니다.

합성 종목 77행·위험등급 77행·업무시계 표본 1행을 넣고 기존 가격 기준일·등급·계산/수신 시각·종목 정보·업무시계 원본의 해시를 전후 비교했다.

- 전체 마이그레이션과 재실행: 77행 보존, 버전 0 부여, 기존 필드 해시 일치.
- ALTER 성공 직후·상태 테이블 생성 전 중단: 기존 값 보존, 전체 SQL 재실행으로 상태 행까지 복구.
- 기존 데이터가 거절할 CHECK를 포함한 ALTER 실패: 컬럼 미생성·기존 행 보존, 정상 SQL 재실행 성공.

실제 엔진 11.8.9-MariaDB-ubu2404, 기본 세션·전역 +09:00. 실패 ALTER 문장의 원자성과 DML 롤백은 확인했으나 여러 DDL 전체 ROLLBACK은 지원되지 않는다. 기존 운영 데이터 분포·실스키마 차이·대용량 소요시간은 이 합성 검증으로 보장하지 않는다.

## 아직 운영을 막는 요소

- 공식 달력 범위 확장과 변경일 종료 시각 검증·연결.
- 실제 NCP OS·볼륨·SQLite 잠금·커넥션 풀 시간대·서비스 간 HTTP와 스케줄러 확인.
- 공용 풀을 KST로 변경할 경우 기존 SYSTEM_CLOCK 기준값에 미치는 영향 검토. 세션 UTC는 현재 구현에서 지원해 제공하는 모드가 아니라 차단 조건이다.
- 운영 DB 실스키마 차이와 백업·복원, 배포/재기동·네트워크 단절·DB 전환 등 실환경 복구 검증.
- 현재 실제 HTTP 하네스는 로컬 Windows Python 가상환경에서 검증했다. NCP Linux 컨테이너에서 같은 테스트를 실행한 결과는 아직 없다.
- 자동 동기화·운영 DB 이관·NCP 배포는 비활성/미실행 상태다.

추가 DB 테이블·컬럼은 필요하지 않았다. 기능 재구현 대신 검증 하네스·추가 테스트·공유 문서만 추가했다. 상세 운영 점검표는 OPERATIONS.md, 데이터 계약은 CONTRACT.md를 따른다.
